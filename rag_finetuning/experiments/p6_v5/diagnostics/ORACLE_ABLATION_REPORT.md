# P6-v5 诊断：Oracle Evidence Ablation

> **只做推理，不改模型权重，不训练；只用 hard_dev，不用 test_v5。**
>
> - 全部数字来自自动规则评分（评分器 v4.0.1），状态为 provisional。
> - 条件 C / D 向模型提供了必要事实清单，**只用于诊断，不代表真实能力**。
> - 根因归类和争议题预审都是 AI 判断，不是人工结论。

## 1. 设置

| 项目 | 内容 |
|---|---|
| 题目 | hard_dev 中 43 道多证据题（评分器 v4 `is_multi_v5`），共 124 条必要事实 |
| 模型 | 3B Base（A）、3B v4 种子 42（C42）、7B Base（D） |
| 解码 | 与第一轮完全相同：3B 用 transformers 4-bit 贪心，7B 用 Ollama temperature 0 / seed 42；max_new_tokens 384 |

四种条件：

| 条件 | 输入 | 说明 |
|---|---|---|
| A | 原始 RAG 上下文 | 复用 hard_dev 第一轮输出（同模型、同冻结输入、同解码），不重跑 |
| B | 只给 Gold Evidence | 按原先后顺序保留金标准片段，删除全部干扰片段（平均每题删 2 个） |
| C | B + 必要事实清单 | 每条写出所在原句和片段 ID |
| D | C + 生成后逐项事实检查 | 有遗漏时再调用一次模型做最小修订；修订若引入证据外数字或无效 ID，就退回 C 的答案 |
| Brev | B 的证据顺序完全颠倒 | 只对 B 条件失败的题运行 |

**Gold Evidence 充分性核查**（`oracle_ablation/gold_check.json`）：43 题的 124 条必要事实，出处片段全部在金标准中，事实文本都能在原文中找到；参考答案只用金标准证据时，自检全部通过。

- “引用错误（内容完整）”在 3B Base 上随条件增加：3B Base 在答案中把多个 ID 堆在一起或漏写方括号，属于格式与归属问题，不是内容问题。

## 5. 证据顺序

把 B 条件失败的题的金标准顺序完全颠倒（Brev）：

| 模型 | B 失败题 | 颠倒后变为完整 |
|---|---|---|
| 3B Base | 16 | 5 |
| v4 s42 | 19 | 6 |
| 7B Base | 14 | 7 |

- 第一轮 8 对顺序对照题（原始上下文）中，至少一个模型的结论随顺序改变的有 7 对；改变的方向不一致，没有出现系统性的“只用第一个证据”。
- 解读：**顺序会显著影响结果，但不是固定偏向某个位置**，更像是“选哪些事实”不稳定。Brev 只在失败题上运行，缺少对称对照（没有测“原本成功的题颠倒后是否会失败”），所以这里只能说明顺序敏感，不能估计它的净效应。

## 8. 对指定问题的回答

### Gold Evidence 能修复多少道题？

不多，而且对 v4 是负的：

| 模型 | 修复 | 弄坏 | 净变化 |
|---|---|---|---|
| 3B Base | 8 | 3 | +5 |
| v4 s42 | 3 | 5 | **−2** |
| 7B Base | 8 | 4 | +4 |

**删除干扰片段不是主要解法**，v4 的失败不是被干扰片段带偏造成的。

### Fact Checklist 能额外修复多少道题？

在 Gold 的基础上：

| 模型 | 修复 | 弄坏 | 结果 |
|---|---|---|---|
| 3B Base | 8 | 5 | |
| **v4 s42** | **17** | **0** | 24 → **41 / 43** |
| 7B Base | 10 | 3 | 29 → 36 |

清单是三种干预中效果最大的。

### Verify 能否修复遗漏而不引入幻觉？

能，至少在本实验的设置下是这样：

- 修复数：3B Base +9，7B +5，v4 无需修复，3 个模型都没有弄坏任何题；
- 修订后新增证据外数字：0 题；
- 防护规则拒绝了 2 次修订；只有 7B 有 1 题陈述支持变差。

**前提**：检查依赖“知道必要事实是什么”。这里用的是金标准清单，真实系统要靠第一阶段自动抽取。第一轮 hard_dev 的非 Oracle 版本（A_plan）只把 3B 从 22 提到 28，与本实验的 39 之间差距很大。

### 哪些题在提供全部必要事实后仍失败？

见第 6 节。除去 2 题评分器误判和 2 题部分争议，**真错**的只有：

- 3B Base 的 dv_m20、dv_x06；
- v4 的 dv_i01、dv_m24；
- 7B 的 dv_m23（漏答部分）。

### v4 的多证据问题是证据利用问题，还是缺少组合推理能力？

**主要是证据利用问题**：v4 不能稳定判断“回答这个问题需要哪些事实”，而不是缺少把多条事实组合起来的能力。依据：

- 去掉干扰片段对 v4 没有帮助（26 → 24）；
- 一旦明确告诉它需要哪些事实，v4 就能写出完整、有引用的答案（41 / 43，陈述支持 38 / 43），而且清单没有弄坏任何题；
- v4 的主要失败类型在 A、B 条件下都是“事实遗漏”（15、13 题），极少有条件误解或无依据推断；
- 顺序颠倒能让约 1/3 的失败题变完整，说明“选哪些事实”对输入形式敏感、不稳定。

**局限**：清单直接给出了事实原句，组合难度很低。本实验证明 v4 **能**组合，但没有测量它在更复杂推理上的上限，例如需要计算、多条件交叉的题。dv_m20、dv_m23 这类需要推理的题在各模型上仍然出错。

### DPO 相对于改进数据与推理规划是否还有必要？

不能直接下结论，但优先级应当调整：

1. 已知的差距在于**识别必要事实**：v4 不用清单为 26/43，用清单为 41/43。这个差距有两条可行路线：
   - **推理规划**（第一阶段抽取必要事实，再检查覆盖）：不需要训练，可逐步改进，延迟约为 2～3 倍；
   - **偏好学习**（让模型偏好“完整”而不是“漏掉条件”的答案）：要训练，但推理时没有额外成本。
2. DPO 针对的正是“模型能做到，却选择了不完整的答案”这一类错误，**本实验支持它作为一个合理的候选**。但它是否优于改进数据或推理规划，需要在同一个开发集上对照，本实验不能代替这个对照。
3. 建议的顺序：
   - 先改进非 Oracle 的必要事实识别（推理方案 v2：问题拆解 + 相关性过滤 + 覆盖补充），在 hard_dev 上量化“非 Oracle 版本能追回多少差距”；
   - 再用同一批 hard_dev 判断针对性 SFT 和 DPO 的必要性；
   - 推理规划如果能把 v4 提到 35/43 以上，DPO 的边际价值就有限；如果追不回，DPO 更值得做。
4. 无论走哪条路，训练数据都应该教会模型“回答前先列出问题隐含的全部条件”。v5 已准备的偏好对（完整 vs 遗漏条件）与此一致。
