# P6-v5 下一步实验决策（基于 Oracle 消融 + Planning v2 / v2.1，hard_dev）

> 所有依据都来自开发集（hard_dev），自动评分，provisional。**test_v5 没有使用过，仍处于冻结状态。**
>
> 这份文件是**建议**，不会自动执行，任何训练都需要你确认后再开始。

## 1. 现有证据汇总（3B v4 种子 42，43 道多证据题）

| 条件 | 多证据完整 | 含义 |
|---|---|---|
| 原始 RAG | 26 | 现状 |
| 只给金标准证据 | 24 | 去掉干扰片段没有帮助 |
| 金标准 + 必要事实清单（Oracle） | 41 | 模型**能**写全，前提是知道要写哪些事实 |
| 真实规划 v2 / v2.1 | 17 / 20 | 自动抽取召回约 0.88，但精确率约 0.57；生成阶段在长而杂的清单下明显退化 |

7B：原始 RAG 25 → Oracle 清单 36（加检查 41）→ 真实规划 v2 / v2.1 为 17 / 23。7B 抽取召回只有 0.30 / 0.62，瓶颈在抽取。

## 2. 问题出在规划提取，还是答案生成

| 模型 | 结论 | 依据 |
|---|---|---|
| 3B v4 | **答案生成为主**，抽取精确率次之 | 必要事实全部抽到的 31 题里，只有 16～19 题最终写全；生成器会照抄清单编号，还会误答“资料中没有说明” |
| 7B | **抽取提取为主** | 抽取完整的 12 题中有 10 题写全；召回受提示措辞影响很大 |

两者的共同点：**都不能可靠地判断“哪些事实是回答这个问题所必需的”**。3B 把所有事实都标为“必要”；7B 则漏标大量必要事实。

## 3. DPO 是否还有必要

**有必要作为下一个对照实验，但前提是数据质量过关。** 理由：

1. Oracle 结果说明，v4 的失败是“能做到但没有做到”：它会组合，但不会主动写全。偏好学习针对的正是这种行为。
2. 推理时的真实规划，在两个模型上都没有超过原始 RAG，而且延迟更高。**在开发集上，“改进推理规划”这条路线目前没有显示出收益。**
3. 但两次规划只是两次迭代，不能证明规划路线不可行：
   - 7B v2.1 的陈述支持从 18 提到 28；
   - 召回在提示改进后翻了一倍。

   建议保留为**并行的低优先级方向**，见第 5 节。

## 4. 训练数据的现状（DPO 前必须解决）

7B 起草的 259 道新训练题已经过首轮自动审查（`data/train_v5/assemble_report.json`）：

| 检查 | 结果 |
|---|---|
| 文档独立性 | 训练语料（P6-v1 train 12 篇 + P6-v3 train 32 篇，已排除含注入的来函）与 hard_dev / test_v5 无重名、无片段重复 |
| 与旧测试集重复 | 已把 P6-v1 test、P6-v2 盲测、test_v3、test_v4、hard_dev、test_v5 的全部问题纳入相似度检查（阈值 0.5） |
| Oracle 泄漏 | 起草输入只有训练语料片段，不涉及任何评测集标注 |
| **通过率** | **259 道中只有 14 道通过** |

未通过的原因：

| 原因 | 题数 |
|---|---|
| 有小节没有合格的必要事实 | 206 |
| 参考答案未通过评分器自检 | 32 |
| 引用与小节不一致 | 5 |
| 问题中直接出现必要事实 | 2 |

- 206 题的主要原因是：**7B 出题时往往只用了给定的 2～3 个小节中的一个**。7B 自己就有“只用单一证据”的倾向，所以不能用它来批量生产多证据训练题。
- 在逐条事实层面，481 条中合格 391 条，其余是长度超限 73 条、非原文 11 条、ID 错误 6 条。
- **未通过审查的 245 道一律不进入训练。**
- 尚未完成的审查：rejected 是否为“真实、明确的错误”，需要先生成 3B 候选回答；chosen 是否覆盖全部必要事实，在组装时已用评分器检查；人工复核清单尚未生成。

**结论**：只靠 7B 起草，无法得到足够的多证据偏好数据。自然语料部分只有 14 道题，远远不够。

## 5. 建议的下一步（按优先级）

1. **重建 DPO 数据，暂不训练**：
   - 结构化部分：P6-v4 训练集的 324 条程序化样本，覆盖例外、版本、范围、条件、冲突、部分回答、拒答，答案由构造保证正确；
   - rejected 优先用 3B Base / v3 的真实错误回答，没有真实错误时，按类型删除必要句或换成错误引用（只删减或替换，不编造）；
   - 自然语料部分不再让 7B 一次出完整题，改为：程序挑出需要组合的小节 → 7B 只负责改写问法 → 必要事实由程序从原文抽取；
   - 生成人工复核清单，并标明未经人工验证的风险。
2. **DPO 显存冒烟测试**：只测显存，不正式训练。脚本 `scripts/train_dpo_v5.py` 已就绪，以 v4 种子 42（或 v3）适配器作为策略和参考的初始值，确认 8 GB 能否运行。
3. **小规模 DPO 对照**：在 hard_dev 上比较 v4 与 v4 + DPO 的多证据完整率；两个种子都做，不看 test。
4. **并行的低优先级方向（推理规划）**：
   - 7B：继续改进抽取提示，并把逐片段抽取合并为一次调用以降低成本；
   - 3B：改为“只把必要性高的事实写进清单”，并去掉清单编号，避免被照抄。

   每次改动都只在 hard_dev 上评估，并记录迭代次数，防止对开发集过拟合。
5. **test_v5 只在最终候选冻结后运行一次**。Oracle 的 41/43 不能当作线上可达到的准确率。

## 6. 不建议做的事

- 不建议直接把 Oracle 清单式的提示用于线上：它依赖标注，真实规划无法复现。
- 不建议用这 245 道没有通过审查的 7B 草稿训练任何模型。
- 不建议在 3B 上默认开启任何规划方案：质量下降，而且延迟是原来的约 6 倍。
