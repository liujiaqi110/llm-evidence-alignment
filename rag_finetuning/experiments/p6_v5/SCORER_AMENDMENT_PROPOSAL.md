## 第一部分：非十六进制畸形引用 ID（建议采纳，只影响引用判定）

### 1.1 问题

4.0.2 用两条正则识别引用：
- `CITE_RE`：12 位小写十六进制，前后不是十六进制字符；
- `MALFORMED_RE`：8～11 或 13～16 位十六进制，前后不是字母数字。

下面三种写坏的 ID 会被漏判：

| 编号 | 情况 | 例子（真实输出） | 4.0.2 的结果 |
|---|---|---|---|
| P1 | 混入非十六进制字母 | `d3a46887aml`、`72e16b3La4d0f5`、`d979ml`、`cdc9fd347f7ml` | 两条正则都匹配不上，被当作普通文字；`citation_valid` = True |
| P2 | 大写 12 位十六进制 | 构造用例 `AAAAAAAAAA01` | 两条正则都忽略；不算引用，也不算错误 |
| P3 | 12 位十六进制夹在更长的串中 | `15c4744La1b2c3d4e5f6`、`2017421529999` | `CITE_RE` 从中截出 12 位当作引用：截出的 ID 碰巧是证据 ID 时算有效引用，否则算“编造”而不是“畸形” |

### 1.2 最小复现与回归测试

`rag_finetuning/tests/test_p6v5_scorer_403_proposal.py`，13 项全部通过：

- **`TestCurrent402Gap`**（6 项）：如实记录 4.0.2 的现状。
  - `d3a46887aml` 不被识别；
  - 大写 ID 被忽略；
  - 夹在长串里的 12 位被截出当作有效引用；
  - 引用问题不影响 `content_ok_v4`。
  - 修订生效后，这组测试要按修订记录同步改写。
- **`TestProposal403`**（7 项）：提议规则的期望行为。
  - P1、P2、P3 都能识别；
  - 合法 ID、内部编号 `F1`、引用区域里的普通英文（`OA系统`、`HRMS`）不误报；
  - 只改变 `citation_valid` / `format_ok`，不改变 `content_ok_v4`。

### 1.3 提议规则

只检查**引用区域**，即方括号内和“引用：”这一行：

> 长度 6～20、至少含 2 个数字、十六进制字符占比 ≥ 0.6 的字母数字串，如果既不是合法的 12 位小写十六进制 ID，也不是内部事实编号，就记为畸形 ID。

- 不做大小写归一：提示词要求原样使用编号，写成大写本身就是格式错误。
- 正文中的数字不受影响。证据外数字的判定沿用 4.0.2。

### 1.4 影响评估（只读，`diagnostics/scorer_review/malformed_403_impact.json`、`malformed_403_cases.csv`）

| 范围 | 影响 |
|---|---|
| hard_dev，3B Base（A） | `citation_valid` 51 → 46，`format_ok` 14 → 11 |
| hard_dev，3B Base + 规划（A_plan） | `citation_valid` 53 → 51，`format_ok` 不变（28） |
| hard_dev，其他 10 组（含 **B**、C42、C43、D 和全部规划组） | **不变** |
| 所有组的 `content_ok_v4` 和 `multi_complete_v5` | **不变**（4.0.1 起引用问题不影响内容判断） |
| 偏好对 | 19 对 rejected（全部是真实模型错误）含提议规则下的畸形 ID |
| 训练候选 | 3B Base：P1 51 处、P3 5 处；v3：P3 1 处 |

- 命中的 26 条输出由 AI 逐条查看过（这不是人工审核），看起来都是真正写坏的 ID，没有发现误报：带 `ml`、`La` 这类杂字符，或把一串数字当成引用。
- 对门槛的影响：门槛 6 比较的是候选组相对 B 的 `citation_valid`，B 在新规则下不变，所以只会让新候选里写坏 ID 的输出被如实判错。
- **对偏好数据的影响**：按偏好对构造规则，“含无效 ID 的真实输出不作 rejected”。采纳后应重新运行 `build_pref_pairs`，这 19 对会被排除，并记入 `excluded.jsonl`。它们原本是“含有可解释错误”的真实输出，排除后 H / A 类真实负例会略微减少。这属于按规则删数据，不是新增数据。

### 1.5 建议

采纳 P1、P2、P3，作为修订 4（评分器 4.0.3），在正式训练和 test_v5 之前生效。需要人工确认两点：
1. 规则阈值（长度 6～20、至少 2 个数字、十六进制占比 ≥ 0.6）是否合适；
2. 大写 ID 是否应判为畸形。

## 第二部分：内容匹配的三类争议（**不建议现在改评分器**，等人工审核）

来源：
- hard_dev 全部 12 组的现有输出（4.0.2 重新计算）；
- Oracle 消融（3 个模型 × 4 种条件）。

明细见 `diagnostics/scorer_review/disputes_by_category.csv`（60 行，每行都有空着的人工字段）、`disputes_summary.json`。这 15 道题都已放进 `HUMAN_REVIEW_DASHBOARD.html`：13 道在高优先级 24 题（Q4）中；另 2 道（dv_m01、dv_m09）只在 Oracle 条件下出现争议，单列为补充配额 Q5。

“争议”是 AI 预审的启发式规则挑出来的，**不等于评分器判错了**。

### 2.1 中文数字写法（2 道题，5 次）

| 题 | 必要事实 | 情况 |
|---|---|---|
| dv_m06 | 1张 / 1年 / 8小时 | D、D_plan、Oracle D 条件把“1张”写成“一张” |
| dv_m13 | 优先 / 1张 / 1年 | A_plan、Oracle C / D 条件写成“一张”“一年” |

- 判断难点：“一张”与“1张”语义相同。但如果放开中文数字，就要定义“两 / 二”“十二”“半年”等写法的边界。
- 如果采纳：只把 1～10 的中文数字与阿拉伯数字视为等价，并且量词必须相同。

### 2.2 同义表达（5 道题，26 次）

| 题 | 必要事实 | 答案中的写法 | AI 初看的判断（非人工） |
|---|---|---|---|
| dv_x02 | 50元 / **不变** | “仍为 50 元” | 很可能是评分器漏判，在 7B、v4、Oracle 中多次出现 |
| dv_m24 | **不得拍照**\|录像 | “不可以拍照” | 很可能漏判 |
| dv_m10 | 不予提前更换\|**不能** | “无法回答……” | **不是同义**：3B Base 是整体拒答，“无法”是指无法回答 |
| dv_m11 | 不得导出\|**不能** | “无法” | 需要人工看上下文 |
| dv_m09 | 不再重复报销\|**不能** | “无法” | 需要人工看上下文 |

可见同义规则很容易误伤：“无法回答”中的“无法”不等于“不能导出”。如果采纳，只能针对具体事实列出同义词，例如“不变 ↔ 仍为 / 没有变化”，不能放开通用的否定词。

### 2.3 由证据推算出的数值（9 道题，29 次）

| 题 | 被判为证据外的数字 | 来由 | AI 初看的判断（非人工） |
|---|---|---|---|
| dv_m23 | 5500 | 3000 + 2500，问题里给了两个金额 | 合理推算；多个组反复出现（A / C42 / D 及规划组） |
| dv_m10 | 2400 | 8000 × 30%（规则是“最高不超过 2000”） | **推算对了一半**：2400 超过上限，正确答案是 2000。不应放过 |
| dv_m20 | 300 | 6 人 × 50 元 | 合理推算，但必要事实是“50元 / 团队负责人” |
| dv_m16 | 30000 | 问题里的“3 万元”换算 | 单位换算，不是新事实 |
| dv_x01 | 21 | “晚上 9 点”写成 21 点 | 时间写法换算 |
| dv_m01、dv_x05、dv_x06、dv_m25 | 2、1 | 启发式规则凑出来的小数字（如 3 − 1） | **很可能是巧合**，需看原文 |

- 推算规则很宽：任意两个数字加、减、乘都算“可推算”。所以小数字几乎总能凑出来，2.3 的结果只能当线索。
- 如果采纳，候选做法：只允许问题中给出的数字参与运算，运算结果必须与答案里的计算过程一致。这会让评分器判断“推理是否正确”，复杂度和误判风险都会明显上升。

### 2.4 采纳后的上限影响（只在 hard_dev 上，只是说明利害，不是修订依据）

| 假设采纳 | 可能由 0 变 1 的组（每组最多 1 题） |
|---|---|
| 中文数字 + 同义表达 → `multi_complete_v5` | A、C42、C42_pv2、D、D_plan、D_pv21 |
| 推算数值 → `content_ok_v4` | A、A_plan、C42、C42_pv21、D、D_plan |

- **B 组在任何一类下都不会变化**。上限影响是每组 56 题中最多 1 题，不会改变已有结论（规划组没有超过原始 RAG；v4 没有显著好于 v3）。
- 但对 test_v5 的晋级判定，±1 题就可能跨过 +0.10 的门槛。所以这三类必须在 test_v5 运行之前由人工决定：
  - 修，就写入修订；
  - 不修，就在报告里把它们列为已知局限。
  - 不能等 test_v5 出结果后再决定。
