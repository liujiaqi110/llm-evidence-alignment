# `use_logits_to_keep` 数值等价性测试

脚本：`diagnostics/dpo_logits_equivalence.py`。结果：`diagnostics/dpo_equivalence/equivalence.json`。

> 这是诊断测试：不更新权重，不保存适配器，不是训练。修订 3（`use_logits_to_keep=True`）仍然是 **proposed**，没有生效。

## 1. 方法

| 项目 | 设置 |
|---|---|
| 模型 | 与冒烟测试相同：Qwen2.5-3B-Instruct 4-bit NF4 + `policy` / `reference` 两个适配器，都初始化自 v4 s42；`prepare_model_for_kbit_training` + 梯度检查点 |
| 配置 | 与正式 DPO 相同的 DPOConfig：sigmoid，β 0.1，max_length 1024，max_prompt_length 896，bf16 |
| 样本 | 从 [prompt + 较长回答] ≤ 560 token 的偏好对中按类型轮流各取 1 对，共 8 对（A 2、C 2、E 2、H 2），批大小 1 |
| dropout | 504 个 Dropout 模块全部设为 p = 0；保持 `train()` 模式，让梯度检查点照常生效 |
| 每对计算 4 次 | 关 → 开 → 关 → 开，即 F1 → T1 → F2 → T2。每次都通过 TRL 的 `concatenated_forward` / `compute_ref_log_probs` / `dpo_loss`，并在 `compute_loss_context_manager`（与训练循环相同的 autocast）下完成，然后反向传播 |
| 比较量 | 策略和参考模型的 chosen / rejected logp、DPO loss、全部 14,966,784 个可训练参数（LoRA）的梯度 |
| 噪声对照 | F2 对 F1、T2 对 T1：同一设置重复运行的差异 |
| 分配器 | `expandable_segments:True`，只影响显存分配，不影响数值 |

失败记录也保留了：

- r1：用了 `model.eval()`，梯度检查点随之关闭，第 1 对的前向就显存不足（`logs/diag_equiv_r1_eval_mode_oom.log`）；
- r2：改为 train 模式后完成了第 1 对，第 2 对的反向传播因显存碎片不足（`logs/diag_equiv_r2.log`）。

两次都没有产生结果文件。r3 加入了每次运行后释放显存，8 对全部完成，没有跳过。

## 3. 解读

1. **logp 等价**：开和关之间，四个 logp 最多相差 1.5e-5，量级相当于 bf16 / fp32 混合计算的舍入误差。
   - 同设置重复运行时，logp 完全相同（差为 0）。
   - logp 是 DPO 损失唯一的输入，所以**前向计算是等价的**。
2. **loss 相同这一点没有区分度**：训练开始时策略和参考相同，所以 loss 恒为 ln2 = 0.69315，8 对都是这个值。
   - 更有意义的是 logp 和梯度。
   - 冒烟测试 r4 的第 3～10 步（策略已经偏离参考）在开 `use_logits_to_keep` 时 loss 和 margins 正常变化，但当时没有关闭该选项的对照（关掉会 OOM）。
3. **梯度近似等价，但不是逐位相同**：余弦相似度 ≥ 0.99991，相对 L2 差 0.83%～1.26%。
   - 在 6 / 8 对中，同设置重复运行本身就有 0.26%～1.08% 的差异：反向传播在 GPU 上不是确定性的。开和关之间的差异与这个噪声同一量级，大约是它的 1～3 倍。
   - 在 wechat_post 和 ssl_cert 两对上，关闭时重复运行的噪声为 0，开和关之间仍差约 1%。这说明存在一个**系统性的小差异**：两种设置下 lm_head 的矩阵乘法形状不同（只算回答位置 vs. 算全部位置），bf16 下的累加顺序也不同，这是最可能的原因。
   - 这个差异远小于一个优化步本身的变化量。学习率 2e-5 时，梯度方向的差异（余弦 0.99991）对训练轨迹的影响，预计远小于随机种子的影响（v4 的 s42 与 s43 之间的差异）。但**本测试没有直接验证训练结果是否相同**。
4. **显存**：在约 500 token 的样本上，开 `use_logits_to_keep` 可以省下 1.1～1.3 GB 峰值显存（关约 4.7～4.9 GB，开约 3.5～3.6 GB）。这与冒烟测试中“只有开启时才能运行”的结论一致。

## 4. 结论（provisional）

- `use_logits_to_keep=True` 与 `False` 在**前向计算**上等价：logp 差 ≤ 1.5e-5。
- 在**梯度**上近似等价：余弦 ≥ 0.99991，差异在 bf16 舍入与 GPU 非确定性的量级。
- 它不改变 DPO 的损失定义。
- 支持修订 3 的“数学等价”说法，但需要补一句限定：**数值上不逐位相同**。
- 修订 3 继续保持 proposed，由用户批准正式训练时一并确认。

**局限**：
- 只测了 8 对短样本（≤ 560 token）。关闭选项时，长样本放不进显存，没法在长样本上对照。
- 只测了训练开始时（策略 = 参考）的梯度。
- 没有比较多步训练后的结果。
