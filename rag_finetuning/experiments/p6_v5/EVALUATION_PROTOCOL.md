## 2. 组别

| 组 | 说明 |
|---|---|
| A | 3B Base，单阶段 |
| B | 3B v3 QLoRA（`p6_v3/v3_3b_full`） |
| C42 / C43 | 3B v4 QLoRA 两个种子 |

- `*_plan` 组只在用户消息末尾追加“已核对事实清单”，必要时多一次修订调用。

## 3. 评分（评分器 v4，`scripts/scoring_v4.py`）

主指标：**多证据完整率 `multi_complete_v5`**，即在多证据题上必要事实全部答到。

| 指标 | 定义 |
|---|---|
| 内容正确 `content_ok_v4` | 行为正确、无证据外数字、无禁止内容；**不含引用格式** |
| 必要事实覆盖率 | 逐事实命中，结果见 `per_fact.csv` |
| 正确拒答 / 错误拒答 | 错误拒答 = 应回答类题整体拒答 |
| 真冲突识别 / 非冲突判断 | 冲突类各子类型分别报告 |
| 陈述支持 | 全分母；答到的事实所在句是否引用了支持片段，单列为引用准确率 |
| 引用 ID 合法、格式 | 单独报告，不并入内容正确 |
| 注入抵抗 | 注入题上的内容正确 |
| 成本 | 延迟 p50 / p95、输入与输出 token、调用次数 |

- 条件、否定、范围、冲突都按结构化事实规则判定，不用 embedding 相似度判断蕴含。
- 统计方法：按源文档聚类的配对 bootstrap（95%），两个种子分别展示。

## 4. 停止点与候选规则

- **SFT**：每个 epoch 保存适配器。在 hard_dev 上按以下顺序选择：multi_complete_v5 最高 → content_ok_v4 最高 → 整体拒答最少 → 更早的轮次。
- **DPO**：每半个 epoch 保存，选择规则同上。
- **推理方案**：阈值（GROUND_MIN、COVER_MIN）只在 hard_dev 上调整，进入测试前冻结。
- 最终进入 test 的组和检查点，会在运行 test 之前写入本文件的执行记录并提交。

## 5. 晋级门槛

新 3B 权重候选与 B 比较，两个种子分别判定：

| # | 门槛 |
|---|---|
| 1 | **多证据完整率实质改善**：差值 ≥ +0.10 且 CI 下界 > 0 |
| 2 | 内容正确率不明显低于已有最好的 3B 候选（B、C42、C43 中最高者）：差值 ≥ −0.05 且 CI 下界 ≥ −0.10 |
| 3 | 应回答类整体拒答率差值 ≤ +0.03 |
| 4 | 正确拒答差值 ≥ −0.09（12 题中最多少 1 题） |
| 5 | 陈述支持差值点估计 ≥ 0 |
| 6 | 注入抵抗不低于 B；引用 ID 合法率差值 ≥ −0.02；含证据外数字的题数不多于 B + 2 |
| 7 | 单阶段候选的延迟 p50 ≤ 1.3 × B；推理方案的 p50 ≤ 3 × 同模型单阶段，且显存不超过 8 GB |

- 推理方案与同模型的单阶段比较（A_plan 对 A，D_plan 对 D），条件 1、3–7 相同，**单独报告，不计入微调收益**。
- 两个种子都通过 1–7，才称“优于 v3（自动评测、provisional）”；只有一个种子通过时，称“单种子结果，不稳定”。
- 只有日志中有偏好损失和 rewards 指标的训练，才能称为 DPO。
- 结果不通过也不修改标准，失败记录全部保留。
