# P6-v3 验收报告：高质量 SFT 数据工程与 QLoRA 优化实验

> 日期：2026-11-23。分支 `feature/rag-sft-v3`，基于 P6-v2 的 `2e8e2e6`。
>
> **所有数字均为自动规则评分（评分器 v2）。人工审核尚未进行，结果一律为 provisional。** 辅助 LLM 评审单独列出，与规则评分、人工审核分开。
>
> 独立测试集 test_v3（81 题）在训练前封存（`9b982e7`）。评估方案、门槛与评分器在训练前冻结（`c1189bf`）。每个模型组在 test_v3 上只生成了一次。

## 0. 八个验收问题

**1. v1 为什么发生过度拒答？**

训练管线本身没有实现错误。逐条验证的结果是：Chat Template 一致；只对回答计算 loss（99/99 条）；EOS 为单个特殊 token；padding 已屏蔽；没有打包；LoRA 覆盖全部 7 类线性层；三个集合之间文档零泄漏。

原因在数据。可验证的证据有：

- **拒答目标高度重复**：同一句“根据提供的资料无法回答该问题。引用：无”在训练目标中**逐字重复了 28 次**，是出现最多的目标。它只占 loss token 的 5.8%，但短、固定、高频，很容易被背下来。
- **同题异行为**：13 个“删除金标准派生”的拒答样本，与对应的回答样本问题相同、行为相反。其中 2 条的剩余证据还含间接证据，标签本身有问题。
- **对数概率测量**：在应回答题上，v1 把拒答句的平均 token 对数概率从 −1.53 抬到 −0.23，高于参考答案的 −0.27。拒答句比正确答案更可能被生成的题数，在 P6-v1 测试集上从 0 变为 13/28，在 P6-v2 盲测集上从 1 变为 24/37。
- **loss 为什么看不出问题**：val loss 只衡量 teacher forcing 下参考答案的似然。参考答案的似然确实提高了，但拒答句提高得更多，贪心解码时两者直接竞争，loss 反映不出这种竞争。证据见第 2 节。

**2. v3 数据改进了什么？**

- 删除了 13 条派生拒答，不再用“删除金标准”的方式批量制造拒答。
- 拒答比例从 28% 降到 19%。拒答证据全部来自其他文档，并逐条确认必要事实不在证据中。拒答句改为与具体缺失内容挂钩的“有依据的拒答”。
- 新增部分回答 24 条、多证据 45 条（v1 为 18 条）、冲突族 15 条（区分真冲突、版本覆盖、适用范围、条件差异）、注入 28 条。
- 每条陈述都附有逐字证据片段。自动检查全部通过：同题异行为 0、重复问题 0、伪造引用 0、片段与来源不符 0、文档泄漏 0。
- 数据从 1.0 版修正到 1.1 版：AI 抽检发现 24% 的陈述是残句，于是把陈述改为完整原句，残句从 65 条降到 3 条。

已知不足：

- 冲突族规模太小（真冲突只有 6 条）。
- 新增的正样本由 7B 起草，部分问题比答案范围更大（问大答小）。

详见 DATASET_CARD。

**3. 3B 能否在 RTX 4060 8GB 上完成训练？**

**能。** Qwen2.5-3B-Instruct 4-bit NF4 QLoRA：

- 120 步，用时 21 分钟。
- 显存峰值 allocated 5.1 GB、reserved 6.8 GB，没有 OOM，没有溢出到共享内存。
- 冒烟测试：前向 / 反向显存峰值 5.0 / 5.9 GB；10 步训练 loss 从 0.97 降到 0.34。

**4. 同规模 QLoRA 是否真正优于 Base？**

- **3B：在自动评测上优于 Base，按预设门槛暂定通过。**
  - test_v3 内容正确率 47 → 58/81，+0.136，按文档聚类的 bootstrap CI [+0.046, +0.236]。
  - 两个回归集上也都复现：+0.255 [+0.091, +0.355]、+0.159 [+0.053, +0.246]。
- **1.5B：未通过。**
  - 内容正确率提高了：39 → 51/81，+0.148 [+0.026, +0.261]。
  - 但错误拒答从 0 增至 16/53（+0.302 [+0.196, +0.400]），违反第 ② 条门槛。
  - 用种子 43 复训，错误拒答仍有 10/53。

**5. 微调改善了什么，又损害了什么？**

以 3B 为例（D → E，test_v3）：

- **改善**：
  - 部分回答 5 → 9/11（+0.364 [+0.083, +0.700]）；
  - 错误拒答 9 → 3/53；
  - 引用格式 16 → 78/81；
  - 陈述—证据支持 34 → 45/55（+0.200 [+0.019, +0.375]）；
  - 注入抵抗 2 → 4/6；
  - 必要事实覆盖 43 → 49/68。
- **损害**：
  - 正确拒答 13 → 11/13；
  - 多证据完整 6 → 3/19（常常只答出一个片段的要点）；
  - 非冲突题 5 → 4/7（只读补充规定、忽略原规定）；
  - 推理延迟 p50 从 2.8 秒增至 5.6 秒（LoRA 叠加在 4-bit 层上，未合并）。
- **没有改善**：冲突识别，所有模型（含 7B）都是 0/4。

**6. 是否已经有可信证据证明模型质量提升？**

**只有“自动评测上的、暂定的”证据，还不能称为正式的质量提升。** 支持的一面：

- 3B 的收益在 3 个互不相同的集合上方向一致，聚类 CI 都不含 0。

保留意见：

- 没有人工审核，`HUMAN_REVIEW.csv` 尚未填写。
- 规则评分依赖关键词，与辅助 LLM 评审的一致性有限（见第 5 节）。
- 每个配置只训练了一个种子。1.5B 的种子复训显示，仅换种子错误拒答就能相差 6 题。
- 训练数据由 7B 起草，存在向 7B 风格蒸馏的可能。

**7. 训练成本是否值得？**

- **算力成本很低**：
  - 本机 GPU 训练合计约 89 分钟，覆盖 10 次运行（含 2 次中止和 1 次冒烟）；
  - 7B 起草数据约 2.5 小时，评估约 2 小时；
  - 不需要任何付费资源。
- **人力成本**主要在数据工程与评测，而且人工审核尚未完成。
- **作为研究**，值得：它定位了过度拒答的数据根因，也证明了同规模 3B 可以从高质量 SFT 中获益。
- **作为部署**，不值得：E 仍低于平台当前免费可用、不需要训练的 qwen2.5:7b（F）。
  - test_v3：58 对 67/81（−0.111 [−0.185, −0.042]）；
  - 延迟 p50：5.6 秒对 1.4 秒；
  - 在 P6-v2 盲测集上两者接近：49 对 50/63。

**8. 下一步是否需要 7B QLoRA 或云 GPU？**

**现在不需要。** 理由：

- 7B Zero-shot 在本轮仍是最好的组。
- 7B 也存在的稳定问题，是冲突识别、注入带偏和“只读一个片段”。前两项在训练集中样本极少；冲突识别更适合用检索后的冲突预检测这类工程手段处理。
- 本机 8 GB 无法训练 7B：按 3B 的实测峰值外推，7B 4-bit QLoRA 估计需要 9–11 GB，**未实测**。

建议顺序：

1. 人工审核 test_v3。
2. 以人工审核过的高质量数据扩充冲突、非冲突、多证据样本，并控制部分回答样本在 1.5B 上的副作用。
3. 先在 3B 上验证。
4. 只有当 3B 的收益经人工审核确认，而且 7B 在可训练的类别上有稳定、可复现的缺陷时，才申请单卡 ≥ 16 GB（建议 24 GB）的云 GPU 做 7B QLoRA，**并需要你另行授权**。

## 1. 实验设置

| 组 | 模型 | 训练数据 | 说明 |
|---|---|---|---|
| A | Qwen2.5-1.5B-Instruct@989aa79（4-bit NF4） | 无 | 原始模型 |
| B | A + P6-v1 Adapter | v1 数据（99 条） | 与 P6-v1 完全相同 |
| C | A + v3 Adapter（epoch 2） | data_v3 1.1（315 条） | 训练配方与 B 完全相同 |
| D | Qwen2.5-3B-Instruct@aa8e725（4-bit NF4） | 无 | 原始模型，sha256 已与 HF 公布值核对 |
| E | D + v3 Adapter（epoch 1） | data_v3 1.1 | |
| F | Ollama qwen2.5:7b（Q4_K_M） | 无 | 规模参考组 |

- **推理条件**（所有组统一）：平台 rag_v1.0 Zero-shot Prompt；相同证据及顺序；贪心解码，最多输出 384 token。
- **训练配方**：r = 8、α = 16、dropout 0.05、lr 2e-4、cosine、ga = 8、最多 3 个 epoch、种子 42、只对回答计算 loss、padding 到 128 的倍数。
- **停止点选择**：在 dev_v3 上按预注册规则选择，详见 TRAINING_CONFIG。

**E 与 F 的差异不能归因于微调**，因为两者的规模、权重和推理实现都不同。

## 5. 辅助 LLM-as-Judge（qwen2.5:7b，provisional，非人工）

F 组就是评审模型本身，不参与评审。评审范围是 68 道应回答 / 部分回答 / 冲突题。评审不知道答案出自哪一组，提示与 P6-v1 相同。

| 组 | 忠实 yes / partly / no | 完整 yes / partly / no | 与规则评分在完整性上的一致率 |
|---|---|---|---|
| A 1.5B | 30 / 37 / 1 | 43 / 2 / 23 | 0.69 |
| B 1.5B + v1 | 40 / 27 / 1 | 33 / 1 / 34 | 0.81 |
| C 1.5B + v3 | 43 / 25 / 0 | 34 / 1 / 33 | 0.84 |
| D 3B | 31 / 33 / 4 | 37 / 2 / 29 | 0.77 |
| E 3B + v3 | 39 / 29 / 0 | 40 / 0 / 28 | 0.78 |

**与规则评分的关系**：

- **方向一致**：
  - 1.5B 微调后，忠实度提高（yes 30 → 43）、完整性下降（yes 43 → 34），与规则评分中“必要事实覆盖 48 → 41”一致；
  - 3B 微调后，忠实（31 → 39）和完整（37 → 40）都提高，与规则评分的方向一致，但完整性的提升幅度小于规则评分。
- **一致率只有 0.69–0.84**，规则评分与评审之间仍有 16%–31% 的分歧。
- **评审本身也有偏差风险**：评审模型与被评模型同属 Qwen 家族，而且 v3 新增数据由评审模型 7B 起草。

以上进一步说明，必须人工审核后才能下正式结论。

**结论**：

1. **部分回答样本**：
   - 它是部分回答能力的来源（去掉后从 8/11 降到 1/11），**同时也是 1.5B 过度拒答的主要诱因**（去掉后错误拒答为 0）。
   - 拒答先验诊断印证了这一点：拒答句概率高于参考答案的题数从 16 降到 8。
   - 3B 上同样的数据没有引发过度拒答（3/53），说明这个副作用与模型容量有关。
2. **拒答比例本身不是主因**：提高到 v1 的水平，错误拒答也没有变差，且差异在种子波动范围内。
3. **新增 7B 起草的正样本**：没有带来可测量的收益，可能还有轻微负作用。它们质量偏低（短答、问大答小），说明**数量不能替代质量**。
4. **逐句引用监督**：与粗粒度引用相比，差异没有超出随机性。
5. **v3 的“结构性”数据工程是 1.5B 收益的主要来源**：删除派生拒答、有依据的拒答、部分回答、冲突族、注入、两段式多证据。“去掉新增正样本”的变体比 v1 数据内容正确率 +0.222。
6. **方法学提醒**：单种子的消融差异在 ±6 题以内时不可解读。后续实验需要每个配置跑多个种子。

## 8. 局限

1. **审核**：测试集由 AI 编码助手手写，尚未人工审核；人工复核表的 81 行中有 70 行为高优先级，高优先级的判定条件偏宽。
2. **规则评分依赖关键词与字符重叠**：
   - 推理句、元陈述句可能被误判为无支持；
   - 支持度阈值 0.40 在训练数据上标定（正例通过 0.936 / 负例 0.020），在测试集上的误判率未知。
3. **样本量小**：冲突 4、非冲突 7、注入 6、部分回答 11 道；聚类单位只有 10 篇文档。
4. **种子**：主模型只有一个种子；只对 1.5B 做了一次种子复训，**3B 没有复训**。
5. **dev 集**：dev 与训练数据同源（7B 起草），停止点选择几乎没有区分力。
6. **蒸馏**：新增训练数据由 qwen2.5:7b 起草，E 的收益可能部分来自向 7B 风格靠拢。
7. **种子复训是事后补充的**：看过 test_v3 结果之后才做，只用来估计方差，没有替换任何主模型。
