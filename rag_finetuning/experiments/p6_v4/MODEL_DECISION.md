# P6-v4 模型决策

> 按 `configs/freeze.json → promotion_gate_v4_vs_v3` 预注册的门槛判定。门槛在看到任何 test_v4 输出之前已经提交，判定后没有修改。

## 1. 门槛判定（C 对 B，两个种子分别判定，test_v4）

| # | 门槛 | C42 | C43 |
|---|---|---|---|
| 1 | content_ok 差值 ≥ 0 且 CI 下界 ≥ −0.05 | +0.143 [0.042, 0.243] ✅ | +0.131 [0.040, 0.218] ✅ |
| 2 | **多证据完整差值 > 0 且 CI 下界 > 0** | −0.05 [−0.222, 0.111] **❌** | 0.00 [−0.150, 0.143] **❌** |
| 3 | 整体拒答差值 ≤ +0.05 | −0.108 ✅ | −0.135 ✅ |
| 4 | 正确拒答差值 ≥ −0.10 | 0 ✅ | 0 ✅ |
| 5 | 陈述支持差值 ≥ 0 | +0.014 ✅ | +0.095 ✅ |
| 6 | 冲突子类型分别报告 | 已报告（MODEL_COMPARISON 第 2 节） | 已报告 |
| 7 | **延迟 p50 ≤ 1.2 × B** | 1.25 倍 **❌** | 1.55 倍 **❌** |

按规则，两个种子都需要通过 1–5 才能称“v4 优于 v3”。**两个种子都没有通过第 2 条**，第 7 条也都没有通过。

## 2. 决策

1. **不把 v4（C42 / C43）作为新的推荐适配器。** 按预注册规则，不能称“v4 优于 v3”。
2. **保留 v4 的全部产物**：两个适配器、所有检查点、日志，以及失败的尝试（PAUSED / STALLED）。它们都留在 `<WORKSPACE>\runs\p6_v4`，作为一次“多证据目标未达成”的实验记录。
3. v4 在**整体拒答、例外条件、触发条件、真冲突**上的改善，只记为**观察到的现象**（自动评测、provisional）：
   - 跨测试集（test_v3）时收益缩小且不显著；
   - 冲突改善也没有迁移到 test_v3。
   - 这些不构成更换模型的依据。
4. **平台（P1–P5）不做任何改动**：模型、ACL、RRF、权限逻辑都保持原样。
5. 工程方案 E1、E2 都**不默认开启**：
   - E1 收益小且使答案变长；
   - E2 提升冲突识别，但降低陈述支持。
   - 两者都可作为可选的诊断或提示工具。

## 3. 关于延迟门槛

- 第 7 条未通过，部分原因是 C 组的输出更长：平均 74.5、75.7 个 token，B 为 62.0 个。另一部分原因是测量波动：每组只测一次，桌面程序的显存占用不同，按每 token 折算 C43 比 C42 慢 21%。
- 这些**只是解释，不改变判定**：门槛按预注册口径判为未通过。

## 4. 下一步建议（需要你决定，不会自动执行）

1. **先做人工审核**：
   - `HUMAN_REVIEW_V4.csv` 是 v3 的 81 题；
   - `results/test_v4/per_question.csv` 是 test_v4 的 84 题，附各组回答和空白的人工字段；
   - 人工审核完成前，所有结论都是 provisional。
2. **重做开发集**：本轮开发集是模板生成的，多证据题在训练前就已接近满分，无法用来选模型。下一轮应使用手写、且 Base 模型明显答不好的多证据开发题。
3. 多证据问题更可能需要：
   - 用已存档的 hard_negative_answer 做偏好数据；
   - 或改为检索侧 / 生成后的覆盖检查（E1 思路的可读版本），而不是继续加 SFT 模板数据。
4. **暂不建议训练更大的模型**，理由见 REPORT.md 第 8 问。
