## 2. 新增结构化样本（324 条，36 个训练主题）

**生成方式**（`scripts/build_v4.py`）：

- 每个主题有一张随机参数表：两个审批角色、提前天数、金额阈值、期限、次数上限、例外条件、费用、违规处理、适用部门、触发条件；
- 由参数表渲染出制度文档（5 节）、修订与补充通知（3 节）和未注明日期的运营通知（1 节）；
- 由同一参数表推出问题与答案：答案逐句引用支持片段，每个必要事实都标注了支持片段（`fact_cids`）。
- **答案由构造保证正确**，不经过任何 LLM。

| 类型 | 条数 | 对应指令要求 |
|---|---|---|
| multi2：两片段联合（申请审批 + 期限） | 36 | 两个 Chunk 联合决定答案 |
| multi3：三片段联合（审批 + 次数 + 费用） | 36 | 三个 Chunk 联合决定答案 |
| exception：例外条件下的期限与审批人 | 36 | 一般规则 + 例外规则 |
| threshold_trap：金额超过阈值须加签 | 36 | 看似完整但遗漏必要条件（见下文） |
| override：修订通知覆盖旧规定 | 14 | 新制度正式覆盖旧制度 |
| old_still：修订后未修改的部分仍按旧规定 | 10 | 旧制度仍适用于未被覆盖的范围 |
| scope_in / scope_out：部门补充规定 | 13 / 11 | 不同部门适用不同政策 |
| cond_in / cond_out：特殊时段 | 13 / 11 | 条件不同但不构成矛盾 |
| conflict：未注明日期的运营通知与原制度冲突 | 20 | 两个同时有效的规定发生真正冲突 |
| same_conclusion：取值不同但结论一致 | 16 | 数值不同 ≠ 冲突 |
| partial：已知部分 + 未说明部分 | 36 | 证据只能支持部分结论 |
| refusal：同文档难负例，信息在参数表中不存在 | 36 | 证据不足拒答 |

**冲突族**：每个主题随机抽 3 种。冲突族合计 108 条，其中真冲突 20 条（v3 只有 6 条）。

**“看似完整但遗漏必要条件的错误答案”**：threshold_trap 的每条样本都附有 `hard_negative_answer`，例如只写“由部门负责人审批”、漏掉“超过金额阈值须加签”。

- 这类错误答案**只存档，不参与 SFT**。SFT 只学习正确答案，错误答案留作后续偏好学习（例如 DPO）或评测使用。
- 对应的正确答案明确写出“超过阈值，还须经某某审批”。

## 4. 已知局限（如实说明）

1. **模板化**：
   - 新增样本来自 13 种题型模板，每种有 3–4 种问法。不同主题之间的问题句式相近，近重复 22 对。
   - 这些样本考查的是不同文档里的不同数值和角色，**有独立的信息价值**，但语言多样性明显低于手写数据，模型可能学到模板措辞。
2. **语义生硬**：参数是随机组合的，部分搭配不自然，例如“绿植摆放的使用期限”。
3. **与测试集同一作者**：
   - test_v4 由 AI 编码助手手写，训练模板也由同一助手设计；两者的写法不同，但结构类型相同（这是有意的，目的是学习这类技能）。
   - 风格上的相近无法完全排除，问题相似度最大为 0.345。
4. **v3 部分原样保留**：v3 中“问大答小”、部分回答跨文档拼接等问题依然存在（见 P6-v3 DATASET_CARD），没有清洗，以保证单因素对照。
5. **人工审核**：新增样本没有经过人工审核。答案正确性由构造保证，但问题本身是否自然、是否有歧义，需要人工抽检。
